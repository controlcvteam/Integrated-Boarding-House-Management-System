The Backlog outlines the main CRUD features of a Boarding House Management System, divided into four major modules: Tenant, Room, Payment, and Maintenance Request. Each module includes user stories and acceptance criteria for creating, viewing, updating, and deleting records.

1. Tenant — Jan Marinelle Auditor

The system allows an administrator to:

Create tenant records with required-field validation.
View tenants through a list and search for specific records.
View detailed tenant information.
Update tenant information with validation.
Delete tenant records with a confirmation step.

The goal is to keep tenant information complete, accurate, and up to date.

2. Room — Kaye Castro

The Room module allows administrators to:

Register new rooms with room number, type, capacity, rental fee, and availability.
View a list of all registered rooms.
View room details.
Update room information with validation.
Delete rooms after confirmation.

This module is intended to help administrators organize available accommodations and assign rooms efficiently.

3. Payment — Britney Lumod

The Payment module focuses on managing rental transactions. Administrators can:

Record payments and automatically update the tenant's balance/status.
View payment details.
View, search, filter, and sort payment records.
Edit payment information.
Delete incorrect or duplicate payments with confirmation.

The main purpose is to ensure rental transactions are properly recorded and balances remain updated.

4. Maintenance Request — Mark Daryl Rey Guina

The Maintenance Request module allows tenants and administrators to manage reported issues:

Tenants can submit maintenance requests.
New requests start with a Pending status.
Administrators can change the status to Pending, In Progress, Resolved, or Rejected.
Managers can view request lists and details, including descriptions, priority, requester, date, and attachments.
Administrators can edit details, add remarks, and update status.
Requests can be deleted after confirmation.
Overall Summary

The backlog defines a complete CRUD-based system for managing a boarding house. Its four core areas are:

Tenant → Room → Payment → Maintenance Request

Each feature has clearly defined user stories and acceptance criteria, making the backlog useful as a guide for development, testing, and wireframing. The main users are administrators/managers and tenants, with administrators handling most management functions while tenants primarily submit and monitor maintenance requests.
